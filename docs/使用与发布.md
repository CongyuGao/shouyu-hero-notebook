## 现在在这台电脑上使用

- 普通查看：<http://localhost:3000/>
- 你自己的管理工作台：<http://localhost:3000/manage?page=workspace>
- 共同编辑者的密码入口：<http://localhost:3000/edit?page=workspace>

这些是本机预览地址；本地开发服务需要保持运行，不能把 localhost 发给别人当作公网地址。在别人的电脑上，localhost 指的是对方自己的电脑。

## 由你设置和更改编辑密码

1. 进入你自己的管理工作台，点“密码与分享设置”。
2. 在“编辑密码”中输入两次密码，点“保存编辑密码”，确认后保存。建议使用20位以上随机密码，不要使用QQ号、生日或重复字符。
3. 将“密码验证入口”复制给共同编辑的人，另行私发密码。他们不需要ChatGPT账号。
4. 你以后可在同一位置设新密码，无需找回旧密码。修改成功后，旧密码、已验证的旧编辑会话及以前的特殊编辑链接全部失效。
5. 其他人即使知道密码，也无法改密码、管理权限或生成特殊编辑链接。只有经站点所有者身份验证的你能做这些操作。

密码不是你的ChatGPT密码，请独立设置，不需要发到聊天或写进代码。共同编辑者持相同密码，无法据此区分具体编辑者。不要共用你的所有者账号。

本地预览仍使用仅供这台电脑的开发模拟身份。Cloudflare 公网版本使用独立站长密码，完全忽略开发模拟身份与 Sites 身份请求头，不能把开发服务当公开服务器。

## 你自己的站长密码

Cloudflare 管理入口是公网地址加 `/manage?page=workspace`。首次密码保存在这台电脑项目内的 `outputs/cloudflare-owner/站长初始密码.txt`，请放进自己的密码管理器，不要发群。它与分享给协作者的“编辑密码”不同，系统不允许两者相同。

登录后，在工作台最下方“站长密码”中输入当前密码和两次新密码即可更改。站长密码至少20个字符，建议使用密码管理器生成的随机密码。更改成功后，所有站长会话失效，共享编辑密码关闭，旧编辑链接和编辑会话也会作废。你需重新登录并设置新的共享编辑密码。

站长和编辑登录均最长保留12小时。只读地址即使在你的浏览器里也不会显示私人草稿。无须绑卡开通 Cloudflare Access，也不需要协作者拥有 ChatGPT 或 GitHub 账号。

## 保存未完成的攻略

选英雄 → 编辑核心、小天赋、雕文、铭文和流派 → “保存草稿”。成功后窗口关闭，并返回工作台的“待完成攻略”。这里显示英雄、流派和保存时间，点“继续完成”可接着写。

普通玩家看不到草稿。已发布攻略再次保存草稿时，玩家仍看到此前的公开版本；只有你或其他获授权编辑者点“发布”后才更新公开内容。发布成功后该攻略移入“已发布攻略”。

## 分享只读与可编辑入口

- “只读链接”可以发QQ群：只显示已发布攻略。
- “密码验证入口”不包含密码，别人需输入密码才能编辑。
- 特殊编辑链接无需密码，但属于独立凭据，拿到或被转发的人都能编辑。可设1小时、1天、7天、30天，随时重置或作废。改密码也会作废这些旧链接。

只读预览只改变你当前的查看方式，不会自动收回别人的编辑权限。要收回权限，请更改/关闭密码，或作废对应特殊链接。

## 你自己公开发布的步骤

网站已改为你自己的 Cloudflare Workers + D1 方案。日常写攻略不用重新部署：在公网工作台保存/发布即可。只有修改网站界面或代码时，才需要重新部署。

在装有 Node.js 22.13+ 和 pnpm 的电脑上：

1. 下载你的 GitHub 私有仓库，在终端进入项目文件夹，运行 `pnpm install --frozen-lockfile`。
2. 运行 `pnpm exec wrangler login --scopes account:read user:read workers_scripts:write d1:write`，在浏览器登录你自己的 Cloudflare 账号并授权。不要把凭据发到聊天或仓库。
3. 有新增数据库迁移时，运行 `pnpm exec wrangler d1 migrations apply shouyu-notebook-db --remote --config wrangler.cloudflare.jsonc`。这会按记录应用新增表结构，不能删除旧数据库重建。
4. 运行 `pnpm deploy:cloudflare`，等待明确的成功结果及 HTTPS 地址。不要单独运行旧的 `pnpm build` 来发布 Cloudflare，因为旧命令是保留的 Sites 构建。
5. 核对公网普通地址能阅读、管理地址需要站长密码。网站数据放在 D1，正常重新部署不会覆盖已保存攻略或密码。

本机曾遇到 Node 双栈连接 Cloudflare 授权端点超时，以下设置只影响当前终端进程，可在遇到同类错误时使用：

```sh
export NODE_OPTIONS="--no-network-family-autoselection --dns-result-order=ipv4first"
export WRANGLER_WRITE_LOGS=false
```

Cloudflare 托管和 D1 使用免费额度，不绑定你这台电脑的开关机。免费服务不等于无限用量或永远保证可用；达到额度可能暂停请求，不要在未确认费用时升级付费计划。[Workers 价格](https://developers.cloudflare.com/workers/platform/pricing/)、[D1 价格](https://developers.cloudflare.com/d1/platform/pricing/)。

### 忘记站长密码怎么办

只有持有你 Cloudflare 部署账号权限的人才能离线重置。以下操作会撤销所有站长和共享编辑权限，请仅由你操作：

1. 运行 `node scripts/prepare-owner.mjs reset outputs/owner-recovery-01`，目录必须不存在。它在本机生成新随机密码和重置 SQL，不在终端打印密码。
2. 运行 `pnpm exec wrangler d1 execute shouyu-notebook-db --remote --config wrangler.cloudflare.jsonc --file outputs/owner-recovery-01/owner.sql`。
3. 成功后打开该目录的 `站长初始密码.txt`，用新密码登录，并重新设置共享编辑权限。重置文件只留在自己电脑上，禁止上传 GitHub。

普通重新部署不要执行重置命令。初次初始化脚本使用 INSERT OR IGNORE，不会覆盖已经设置的站长密码。

### 此前为什么没发出去

此前验证到的错误发生在上传部署包阶段：上传连接约60秒后超时，尚未得到公网部署地址。这个错误不是“等待审核”的提示；可能涉及连接、代理或上传服务，不能据此断言一定是你的网络。保存的早期版本不是最新网站，不应为了上线而退回它。

### GitHub与网站上线的区别

私有仓库 <https://github.com/CongyuGao/shouyu-hero-notebook> 保存源码、素材、迁移文件和已确认的初始公开资料。它不包含编辑密码、登录会话、本地数据库或私人草稿。

以后在网页里保存的内容进入网站数据库，不会自动提交到GitHub。本次同步代码也不是持续自动备份。数据库需另行导出/备份；攻略编辑器可导出攻略JSON。

当前项目有后端鉴权与D1持久化，不能只启用GitHub Pages就保留所有编辑功能。Cloudflare 的配置已单独保存在 `wrangler.cloudflare.jsonc`，原 Sites 配置也保留；不需要把私有仓库改公开。
