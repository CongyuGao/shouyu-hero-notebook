# 守御手册

手机优先的无尽守御天赋与流派攻略平台。公开阅读，仅管理员指定的成员可编辑。

## 范围

- 首页只显示已经发布攻略的模式英雄，**不会把官网全英雄目录当成模式英雄池**。
- “阅读前瞻”是位于英雄攻略之前的一级页面；指定编辑成员可修改标题、简介、章节，添加常识/须知、调整顺序并保存公开。初始含文档常识整理和评级/雕文说明，资料矛盾与作者观察单独说明。前瞻与英雄攻略、两种资料库、评级标准分别持久化并做版本冲突保护。
- 每英雄默认6个核心、24个小天赋，按技能分为2核心＋8小天赋；每技能核心二选一并自动替换。按用户要求，每流派跨技能最多选择6个小天赋；第7个触发弹窗但不修改已有选择，服务端也拒绝超额。两核心始终保留，选中高亮、未选降亮度，不展示推荐等级。
- 每英雄支持1至8个独立流派：名称、特点简介、详细备注、核心、小天赋、六个雕文与铭文配置分别保存，并支持流派直达链接。另有全英雄共用的攻略备注。
- 共享雕文库与通用五级铭文库，只有指定编辑成员可修改。雕文点击名称或图标弹出完整说明和原始卡片；铭文按三色筛选，每色最多10枚，整套最多30枚。
- 铭文属性使用十进制定点运算按数量合计，固定值与百分比各自累加。自定义效果无法可靠解析时会提示未计入，不默认为零、不猜测名称映射。
- 英雄梯度包含T0、T0.5、T1、T1.5、T2、T3及未评级。支持首页筛选、点击徽章查看对应标准、编辑评级理由和全站判断条件。评级是团队观点，不是官方结论。
- 草稿和公开版本分开保存，支持撤下、最近20次历史导出、JSON导入/导出。
- 英雄列表与攻略页显示公开版本最近更新时间。超过30天显示版本变化提醒（不直接判定失效）；保存草稿不刷新公开更新时间。
- D1持久化、参数绑定、服务端权限、版本冲突保护；管理员按ChatGPT登录邮箱管理编辑成员。

## 数据边界

2026-09-06核验官网公开英雄目录（132条记录），这里只用于编辑选名称和头像。其记录数量不是无尽守御可用英雄数。

来源：https://pvp.qq.com/web201605/js/herolist.json

用户给出的 https://github.com/lengyibai/wzry 是常规王者资料项目，不包含可直接导入的完整无尽守御小天赋、模式雕文或核心流派数据。本项目没有复制该仓库代码，也不导入排位装备。

按用户要求先录入亚瑟，来自 IMG_3111.PNG—IMG_3116.PNG。共6核心、24小天赋，保留资料中的3核心、6小天赋选择。旧`picks.selected`仍可迁移为`talentIds`；新版不提供推荐等级。版本日期尚未确认，标记待核验。亚瑟暂按用户举例设为T1.5，理由和测试条件待团队补充。

雕文原始卡片来自用户指定腾讯文档 https://docs.qq.com/doc/DTnNZRUhIcm1Ya3NM?dver= ，共42张，分别14/13/15个初/中/高级条目。`public/glyph-cards/`保存原始333×90卡片，界面以CSS展示其左侧实际图标，未通过AI重绘图标、文字或数值。卡片效果与正文作者机制解析分开保存；来源有差异时不得合并为确定效果。

铭文库来自已取得的官网五级铭文记录，红、蓝、绿各10种。共享库修改不自动覆盖已发布攻略的属性快照，需编辑同步后重新发布。库与梯度标准使用`libraries`表的独立kind和版本冲突校验；全局标准不混入英雄资料。

页面背景和天赋类别图标是原创生成的装饰素材，不是官方技能图标；来源及提示词见`docs/art-assets.md`。主题位于`app/globals.css`，保留减少动态效果的系统偏好。

`data/initial-guides.json`仅用于首次导入用户提供的资料；`lib/initial-guides.ts`用原子批处理 INSERT OR IGNORE 创建资料和历史，不覆盖现有编辑，也不会重新发布已撤下的攻略。数据库结构只由迁移创建，种子数据不进入迁移。

## 开发与部署

使用生成器指定版本，`pnpm install`、`pnpm dev`、`pnpm build`。数据库迁移由Drizzle生成并由Sites部署应用，不在请求中创建表。`db/schema.ts`为结构源。

本地 `.env` 的 ADMIN_EMAIL 使用Sites开发登录账号；生产 ADMIN_EMAIL 仅通过Sites管理。`.env` 不进入源代码或部署包。更改生产管理员需在Sites修改该值并发布，不可从公开界面修改。

`scripts/check-api.mjs`仅可对localhost运行，要求105英雄没有用户数据；创建带唯一TEST_ONLY前缀的临时数据并在finally清理。禁止用于正式站点。测试覆盖鉴权、来源校验、草稿隔离、发布、并发冲突、历史和成员授权。

WebMCP提供查询、打开、开始/填入编辑区和保存草稿，不允许绕过身份和版本检查；发布仍由界面明确操作。当前环境没有支持WebMCP的验证上下文，未声称完成浏览器WebMCP验证。未进行真实QQ/微信设备兼容性测试。
