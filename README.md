# 守御手册

手机优先的无尽守御天赋与流派攻略平台。普通链接只读，持有效专属链接的人无需账号即可编辑。

## 范围

- 英雄页只显示确认的模式英雄池，**不会把官网全英雄目录当成模式英雄池**。按用户提供的 IMG_3141/IMG_3142 录入42位、三批各14位；不自动把旧截图的周次映射成当前周，也不导入截图评级。已发布攻略与待补充头像入口分开标记，未编写英雄不创建伪攻略。编辑可管理批次名称、移组、移出及手动新增确认的英雄；英雄池独立存于`libraries.kind=roster`并做权限和版本冲突保护，移出只隐藏入口，不删除攻略。
- “阅读前瞻”是位于英雄攻略之前的一级页面；指定编辑成员可修改标题、简介、章节，添加常识/须知、调整顺序并保存公开。支持每章最多12张配图，图片地址、形象名称和说明可编辑。初始含模式常识、十级召唤挑战怪、关卡机制及评级/雕文说明，配有12张核对过的原始形象/站位图，未获准确形象的敌人不使用近似图片。正文直接面向玩家，来源收起；经验和待核对数值保留边界。前瞻与英雄攻略、两种资料库、评级标准分别持久化并做版本冲突保护。
- 每英雄默认6个核心、24个小天赋，按技能分为2核心＋8小天赋；每技能核心二选一并自动替换。按用户最新确认，小天赋为每技能8选6，三个技能独立计算（最多6＋6＋6）；该技能第7个触发弹窗但不改变原有选择，服务端同步校验。提供分技能计数、已选总览和直接取消入口；选中使用金色实边/状态标志，未选使用深色卡片。
- 每英雄支持1至8个独立流派：名称、特点简介、详细备注、核心、小天赋、六个雕文与铭文配置分别保存，并支持流派直达链接。另有全英雄共用的攻略备注。
- 所有42位模式英雄均使用同一套完整攻略界面；未发布时显示独立空模板（6核心、24小天赋、雕文/铭文、流派与通用备注），不复制亚瑟的数据、不自动生成数据库攻略。编辑成员可直接点击某个核心、小天赋或搭配入口，打开对应填写窗口；草稿仍私有，公开版本需手动发布。
- 暂时只预留“BUG说明”一级入口与“逐关怪物资料”前瞻标题，后续再补版本、复现条件、每路怪物和数量；不预填未经验证的BUG或关卡数据。
- 共享雕文库与通用五级铭文库，只有指定编辑成员可修改。雕文点击名称或图标弹出完整说明和原始卡片；铭文按三色筛选，每色最多10枚，整套最多30枚。
- 铭文属性使用十进制定点运算按数量合计，固定值与百分比各自累加。自定义效果无法可靠解析时会提示未计入，不默认为零、不猜测名称映射。
- 英雄梯度包含T0、T0.5、T1、T1.5、T2、T3及未评级。支持首页筛选、点击徽章查看对应标准、编辑评级理由和全站判断条件。评级是团队观点，不是官方结论。
- 草稿和公开版本分开保存，支持撤下、最近20次历史导出、JSON导入/导出。
- 英雄列表与攻略页显示公开版本最近更新时间。超过30天显示版本变化提醒（不直接判定失效）；保存草稿不刷新公开更新时间。
- D1持久化、参数绑定、服务端校验和版本冲突保护；邮箱编辑名单已停用，原记录保留但不再授予编辑能力。

## 编辑链接与保存

- `/`始终使用公开阅读模式。即使同一浏览器持有编辑cookie，普通请求也不返回草稿。攻略分享按钮固定生成根路径的只读链接。
- `/edit#key=...`使用256位随机能力密钥，无需注册或登录；入口先清除fragment，再交换HttpOnly、SameSite=Strict、Path=/api cookie（HTTPS下Secure）。密钥只以SHA-256摘要存于D1，不进入源码、日志或公开GET响应。
- 只有原站点所有者可从`/manage?page=workspace`管理链接；该管理入口沿用Sites提供的可信ChatGPT身份，不能直接搬到不清洗身份头的第三方托管。共同编辑者无需ChatGPT账号。
- 可选择1小时、1天、7天或30天有效期，默认7天。到期/作废/重置会在每次服务端验证时生效；实际内容写SQL再次检查链接代次和过期时间，避免鉴权后与撤销的竞态。链接只在生成当次返回，遗失后需要重置。
- 普通读者不能通过请求头单独获得编辑能力；内容修改必须同时具有有效cookie或管理入口的所有者身份。旧`/api/editors`返回410。
- 保存草稿/发布按钮在服务端成功后关闭副窗口并显示成功通知；失败或保存期间发生新修改时保留窗口和内容。工具保存与撤下操作不强制关窗。

## 数据边界

2026-09-06核验官网公开英雄目录（132条记录），这里只用于名称与头像映射。公开英雄池严格取`data/initial-roster.json`的42位（或成员随后确认并保存的名单），普通攻略编辑器不展示全英雄选项。42个头像链接均通过HTTP 200/image/jpeg检查。其来源目录数量不是无尽守御可用英雄数。

来源：https://pvp.qq.com/web201605/js/herolist.json

用户给出的 https://github.com/lengyibai/wzry 是常规王者资料项目，不包含可直接导入的完整无尽守御小天赋、模式雕文或核心流派数据。本项目没有复制该仓库代码，也不导入排位装备。

按用户要求先录入亚瑟，来自 IMG_3111.PNG—IMG_3116.PNG。共6核心、24小天赋，保留资料中的3核心、6小天赋选择。旧`picks.selected`仍可迁移为`talentIds`；新版不提供推荐等级。版本日期尚未确认，标记待核验。亚瑟暂按用户举例设为T1.5，理由和测试条件待团队补充。

剩余 IMG_3117.PNG—IMG_3140.PNG 共24张照片已转录为`data/hero-talents.json`，包含安琪拉、程咬金、狄仁杰、李白，每位6核心、24小天赋；李白有一项名称字形待核对。预置资料用于公开英雄模板和首次填写攻略，不创建推荐流派，不复制截图勾选，不覆写既有攻略。狄仁杰不在已确认轮换名单，保存资料但不自动加入列表。具体边界见`docs/hero-talent-transcription.md`。

雕文原始卡片来自用户指定腾讯文档 https://docs.qq.com/doc/DTnNZRUhIcm1Ya3NM?dver= ，共42张，分别14/13/15个初/中/高级条目。`public/glyph-cards/`保存原始333×90卡片，界面以CSS展示其左侧实际图标，未通过AI重绘图标、文字或数值。卡片效果与正文作者机制解析分开保存；来源有差异时不得合并为确定效果。

铭文库来自已取得的官网五级铭文记录，红、蓝、绿各10种。共享库修改不自动覆盖已发布攻略的属性快照，需编辑同步后重新发布。库与梯度标准使用`libraries`表的独立kind和版本冲突校验；全局标准不混入英雄资料。

页面背景和天赋类别图标是原创生成的装饰素材，不是官方技能图标；来源及提示词见`docs/art-assets.md`。主题位于`app/globals.css`，保留减少动态效果的系统偏好。

`data/initial-guides.json`仅用于首次部署时迁移本地已公开的攻略，保留原公开日期，不打包私有草稿；`lib/initial-guides.ts`用原子批处理 INSERT OR IGNORE 创建资料和历史，不覆盖现有编辑，也不会重新发布已撤下的攻略。数据库结构只由迁移创建，种子数据不进入迁移。

## 开发与部署

使用生成器指定版本，`pnpm install`、`pnpm dev`、`pnpm build`。数据库迁移由Drizzle生成并由Sites部署应用，不在请求中创建表。`db/schema.ts`为结构源。

本地 `.env` 的 ADMIN_EMAIL 使用Sites开发登录账号；生产 ADMIN_EMAIL 仅通过Sites管理。`.env` 不进入源代码或部署包。更改生产管理员需在Sites修改该值并发布，不可从公开界面修改。

`scripts/check-api.mjs`仅可对localhost运行，要求105英雄没有用户数据；创建带唯一TEST_ONLY前缀的临时数据并在finally清理。禁止用于正式站点。测试覆盖鉴权、来源校验、草稿隔离、发布、并发冲突、历史和旧授权入口停用。

`scripts/check-edit-links.mjs`另验证链接生成/轮换/到期/撤销、cookie与普通阅读隔离、无账号保存发布及每技能6项校验。要求本地没有已有编辑链接，拒绝覆盖用户生成的链接；仅清理本次测试记录，并比对真实攻略与全局资料保持不变。`scripts/check-talents.ts`验证每技能8选6、拒绝第7项、取消替换及旧选择兼容。

`scripts/check-hero-presets.ts`验证四位英雄的资料模板可继续编辑、核心/天赋按技能归组、无预选/虚构流派、实例互不污染，并确认42位模式英雄池未被扩充。

WebMCP提供查询、打开、开始/填入编辑区和保存草稿，不允许绕过身份和版本检查；发布仍由界面明确操作。当前环境没有支持WebMCP的验证上下文，未声称完成浏览器WebMCP验证。未进行真实QQ/微信设备兼容性测试。
